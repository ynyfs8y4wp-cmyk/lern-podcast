ANNA: Hallo und willkommen bei der Lernroute Agentifizierung. Heute vier Wörter, die in jedem Entwickler-Meeting fallen: Daten, API, JSON und YAML. Ben, fang vorne an.
BEN: Gern. Daten sind erst mal ganz unspektakulär die einzelnen Angaben, mit denen eure Systeme arbeiten. Betrag, Datum, Kostenstelle, Name. Spannend wird es bei der Frage, wie Programme sich diese Angaben gegenseitig zureichen.
ANNA: Und da kommt die API ins Spiel.
BEN: Genau. Stell dir eine Behörde vor. Du gehst nicht ins Hinterzimmer und wühlst selbst in den Akten. Du gehst an einen Schalter, gibst ein ausgefülltes Formular ab und bekommst ein ausgefülltes Formular zurück. Der Schalter ist die API, auf Deutsch Programmierschnittstelle. Das Reisekostensystem hat zum Beispiel einen Schalter Beleg anlegen und einen Schalter Status abfragen. Und was nicht als Schalter angeboten wird, das geht eben nicht.
ANNA: Moment mal, das heißt, ein Programm darf nur, was der Schalter erlaubt?
BEN: Ja, genau. Das ist Fluch und Segen zugleich. Segen, weil es kontrolliert ist. Fluch, wenn der Schalter fehlt, den man gerade bräuchte.
ANNA: Und das Formular, das über den Schalter wandert, ist dann JSON?
BEN: Richtig. JSON spricht man aus wie den Namen Jason. Das sind Paare aus Feldname und Wert, eingepackt in geschweifte Klammern. Betrag hundertvierundachtzig Euro fünfzig, Kostenstelle siebenundvierzig elf. Für Menschen ein bisschen sperrig, für Maschinen dafür absolut eindeutig.
ANNA: Und YAML? Das klingt wie ein Tier aus den Anden.
BEN: [laughs] Man sagt Jammel. YAML speichert dieselbe Art von Angaben, aber lesefreundlicher. Keine Klammern, sondern Einrückungen wie in einer Gliederung. Im Bild der Behörde ist YAML die Dienstanweisung an der Wand, die festlegt, wie der Schalter arbeitet. Deshalb nutzen Entwickler es gern für Einstellungen, für GitHub-Abläufe oder für die Beschreibung eines Agenten.
ANNA: Jetzt die entscheidende Frage: Warum muss ich das als Nicht-Entwickler wissen?
BEN: Weil hier der Kern von Agenten liegt. Ein Sprachmodell schreibt eigentlich Fließtext, schöne Sätze. Ein System will aber keine schönen Sätze, es will ein korrekt ausgefülltes Formular. Damit ein Agent also wirklich etwas tun kann, muss er an einer API sauberes JSON abgeben. Und der Agent selbst wird immer öfter nicht mehr im Programmcode beschrieben, sondern in einer YAML-Datei. Name, Aufgabe, Regeln, erlaubte Werkzeuge. Microsoft macht das zum Beispiel mit sogenannten deklarativen Agenten.
ANNA: [curious] Zeig mir das an einem Fall.
BEN: Reisekosten nach einer Dienstreise nach Hamburg. Bisher fotografiert jemand Hotelrechnung und Bahnticket, tippt alles ins Portal ab, sucht die Kostenstelle raus, und die Sachbearbeitung prüft jeden Beleg von Hand. Mit Agent sieht das so aus: Er liest die Belege und füllt daraus das JSON-Formular. Datum, Betrag, Art Hotel, Kostenstelle. Dann gibt er es über die API ab. Fehlt ein Pflichtfeld, kommt sofort eine klare Fehlermeldung zurück, und der Agent bessert nach.
ANNA: Und wer passt auf, dass er nicht das Luxushotel durchwinkt?
BEN: Das steht in seiner YAML-Datei. Eine Regel: Hotel über hundertfünfzig Euro pro Nacht geht zur Freigabe an einen Menschen. Die Sachbearbeitung prüft am Ende nur noch die Ausnahmen.
ANNA: Na ja, und was, wenn das System gar keinen Schalter hat?
BEN: Dann hörst du im Team den Satz: Die haben keine API, da müssen wir übers Frontend gehen. Heißt, der Agent müsste sich wie ein Mensch durch die Bildschirmmasken klicken. Das geht, ist aber langsamer und bricht leicht, sobald jemand einen Knopf verschiebt. Ein anderer Klassiker: Das Modell liefert kein valides JSON. Dann hat der Agent das Formular falsch ausgefüllt, etwa eine Klammer vergessen. Dagegen helfen strukturierte Ausgaben, bei denen das Modell zwingend ein vorgegebenes Formular befolgt.
ANNA: Und was sagst du mir als Gruppenleiter?
BEN: [thoughtful] Die Frage, ob ein System eine gute API hat, entscheidet oft mehr über Aufwand und Erfolg eines Agenten als das Sprachmodell selbst. Lass dir zeigen, an welche Schalter der Agent darf und welche fehlen. Und weil YAML lesbar ist, kannst du die Regeln selbst mitlesen, etwa Freigabegrenzen. Wenn jemand sagt, das ist nur ein Konfig-Change im YAML, dann heißt das: kein neuer Code, nur eine geänderte Einstellung. Das ist Kontrolle, ohne programmieren zu müssen.
ANNA: Dann der Merksatz.
BEN: Die API ist der Schalter, JSON das Formular, YAML die lesbare Dienstanweisung. Ein Agent ist nur so gut wie die Schalter, an die er darf.
ANNA: Und die Mini-Übung: Nimm eine echte Reisekostenabrechnung oder Bestellung und schreib auf Papier die fünf wichtigsten Angaben als Paare aus Feldname und Wert untereinander.
BEN: Und schon hast du dein erstes eigenes YAML geschrieben.
ANNA: Bis zum nächsten Mal bei der Lernroute.
