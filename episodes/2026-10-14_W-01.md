ANNA: Hallo und willkommen bei der Lernroute Agentifizierung. Heute geht es um Git und GitHub, also um Repository, Branch und Commit. Ben, das klingt erst mal nach reiner Entwicklerwelt. Warum soll mich das interessieren?
BEN: Weil jeder das Problem kennt, das Git löst. Kennst du Dateinamen wie Vertrag final, Version drei, neu, Korrektur Müller? Irgendwann weiß niemand mehr, welche Fassung gilt. Git ist das genaue Gegenteil davon. Stell dir einen Ordner vor, der sich jede Änderung merkt, mit Datum, Namen und Begründung. Und du kannst jederzeit auf den Stand von letztem Dienstag zurückspringen.
ANNA: [curious] Ein Ordner mit Gedächtnis also. Und GitHub?
BEN: GitHub ist das Haus, in dem dieser Ordner steht. Mit Besprechungsräumen, Postfach und Pförtner. Git ist das Programm, das alles aufzeichnet, GitHub ist das gemeinsame Büro im Internet, wo das ganze Team daran arbeitet. Die Plattform gehört übrigens Microsoft.
ANNA: Gut. Dann die Begriffe der Reihe nach. Was ist ein Repository?
BEN: Ein Repository, kurz Repo, ist ein Projektordner unter Git-Aufsicht. Da liegt alles drin, was zu einem Vorhaben gehört. Programmcode, Einstellungen, Anleitungen. Und, das ist für euch spannend, zunehmend auch die Regeln und Anweisungen eurer Agenten.
ANNA: Und ein Commit?
BEN: Ein Commit ist ein gespeicherter Zwischenstand mit einer kurzen Notiz. Etwa: Freigabegrenze für Bestellungen auf zweitausend Euro erhöht. Das ist wie ein Eintrag im Logbuch eines Schiffes. Der bleibt für immer stehen, man kann ihn nicht heimlich herausreißen.
ANNA: Moment mal, und der Branch? Da steige ich bei Entwicklern meistens aus.
BEN: [chuckles] Das geht vielen so. Branch heißt Zweig. Denk an einen Baum. Der Stamm ist der Hauptstand, der heißt meistens main, und das ist das, was gerade wirklich läuft. Wer etwas Neues ausprobieren will, macht das auf einem eigenen Ast daneben. Bricht der Ast ab, steht der Stamm trotzdem. Erst wenn alles geprüft ist, wächst der Ast zurück in den Stamm. Das nennt man Merge, also zusammenführen.
ANNA: Na ja, klingt schön, aber wo merkt man das im Alltag?
BEN: Nimm euren Agenten für Bestellanforderungen. Er soll eine neue Regel bekommen: Bestellungen über zweitausend Euro brauchen künftig eine zweite Freigabe. Ohne Git steht die Regel in einer Word-Datei und irgendwo im Code. Einer ändert sie, ein anderer überschreibt sie aus Versehen. Drei Wochen später fragt die Revision, seit wann die Grenze gilt und wer das entschieden hat. Und keiner weiß es.
ANNA: [sighs] Das kommt mir bekannt vor.
BEN: Mit Git und GitHub läuft es anders. Zuerst gibt es ein Issue, also einen Aufgabenzettel: zweite Freigabe ab zweitausend Euro, Wunsch aus dem Einkauf. Eine Entwicklerin legt einen Branch an und ändert dort die Regeldatei. Der laufende Agent auf main merkt davon nichts. Sie speichert einen Commit mit Verweis auf das Issue. Nach der Prüfung wird gemergt, und der Agent arbeitet mit der neuen Regel. Fragt die Revision nach, zeigt GitHub mit zwei Klicks, wer, wann und warum. Und geht etwas schief, springt man einfach zurück.
ANNA: Wie reden die Leute im Team darüber? Damit man im Meeting mitkommt.
BEN: Drei Sätze hörst du ständig. Erstens: Ich hab's gepusht, ist aber noch auf meinem Feature-Branch. Heißt, die Änderung liegt schon auf GitHub, aber nur auf dem Ast, noch nicht im laufenden System. Zweitens: Main ist kaputt, wir machen einen Revert. Heißt, die letzte Änderung wird sauber rückgängig gemacht. Drittens: Gibt's dafür ein Issue? Heißt, ist die Aufgabe irgendwo festgehalten?
ANNA: Und was heißt das für einen Gruppenleiter, der selbst keinen Code schreibt?
BEN: Lass dir einen Lesezugang zu den wichtigsten Repos geben. Du musst keinen Code lesen. Aber die Commit-Notizen und Issues zeigen dir, woran dein Team wirklich arbeitet. Und achte darauf, dass Prompts und Regeln der Agenten im Repo liegen, nicht in privaten Dateien. Das ist eure Nachvollziehbarkeit gegenüber Revision, Betriebsrat und Fachbereichen.
ANNA: Du sagst Agenten. Arbeiten die da inzwischen selbst mit?
BEN: [excited] Ja, genau, und das ist der große Bogen. Auf GitHub sind über hundertachtzig Millionen Entwickler unterwegs, im Schnitt kommt jede Sekunde einer dazu. Und mit Agent HQ können verschiedene Coding-Agenten direkt an einem Repository arbeiten, gesteuert über Issues und geprüft wie die Arbeit eines Kollegen. Wenn Agenten selbst Änderungen vorschlagen, ist Git das Sicherheitsnetz. Jeder Schritt bleibt sichtbar und umkehrbar.
ANNA: Dann zum Merksatz.
BEN: Git merkt sich jede Änderung, ein Branch ist die gefahrlose Spielwiese, main ist das, was läuft, und GitHub ist das gemeinsame Büro für Menschen und Agenten.
ANNA: Und die Mini-Übung: Öffne auf GitHub ein bekanntes öffentliches Repository, klick auf Commits und lies die letzten zehn Notizen. Welche verstehst du, und wie würdest du die anderen in Alltagssprache übersetzen? Bis zum nächsten Mal.
